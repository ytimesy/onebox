# セキュリティ・プライバシー
## 最小の攻撃面
アカウント、自由投稿、コメント、DM、写真アップロード、外部URL取得、決済を初版に入れない。
既存サービスの認証Cookie・Google OAuth・SNSトークンを流用しない。
公開originを分け、親ドメイン全体にCookieを設定しない。既存アプリから書き換え可能な共有localStorageを仮定しない。

## 公開情報と秘密
公開: ゲームロジック、公開済み問題、ID、模様、OG。
非公開: 配信キー、将来問題ストック、解答ファイル、公開前の編集記録、詳細集計。
公開distをallowlist生成し、PRIVATE、seed、解答、token、環境ファイルの混入検査を行う。
クライアントで解けるパズルを完全に不正不能とは表示しない。世界順位、賞金、他人への優越を根拠にした課金を作らない。

## 入力とAPI
slug/ID/locale/srcをallowlistと長さで検査。srcやqueryをHTMLへ直挿入しない。
任意URLのサーバーフェッチを実装しない。共有リンクはPUBLIC_ORIGIN配下だけ。
/collectはJSONの上限、Originの確認、レート制限、重複除去、サーバー側時刻付与を行う。
Origin確認だけでbotを防げると仮定しない。過剰受信は停止できるようにする。
匿名の端末内結果は改ざんできる。集計も完全な公式スコアとは扱わない。

## 任意計測
初期状態では第三者広告タグ・クロスサイト追跡を置かない。
詳細イベント計測は明示的な任意同意を得た後のみ。不同意でも同じゲームが遊べる。
同意前イベントを後から送信しない。同意撤回で識別子と未送信キューを消す。
集計用匿名IDとイベントの保持は45日を初期設計値、集約値は180日を目安とし、必要性を定期確認する。
画面内の個人履歴は最大180問までローカル保存する。

氏名、正確な位置、国の強制選択、年齢、連絡先を取得しない。
CDNやホスティングのアクセスログ等が別途存在し得るため、「IPを一切扱わない」「完全匿名」と断言しない。
プロバイダー設定・実装された実態を確認した上で利用者向け説明を作る。この資料は法令適合性の認定ではない。

## ヘッダー/フロント
CSPは同一origin中心で、unsafe-evalを避ける。ヒントWorkerのworker-srcも設計する。
frame-ancestors、X-Content-Type-Options、Referrer-Policy、Permissions-Policyを設定し実機検証する。
共有を利用する場合にweb-shareの権限を自分で塞がない。[S1]
本番source mapの公開方針を決め、mapに秘密が混じらないことを検査する。
依存関係の脆弱性検査は公開前に実行し、未実施を「問題なし」としない。
