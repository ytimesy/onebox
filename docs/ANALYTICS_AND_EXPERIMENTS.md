# 集計・試遊・収益化の判断
## 最初に測ること
アクセスより、実際の操作と新しい参加者への接続を見る。
計測は任意。同意を拒否しても問題や結果保存を制限しない。
匿名IDによる分析は同意した同一ブラウザー単位の推定で、実人数・世界全体を代表しない。

## 指標と分母
| 指標 | 定義 |
|---|---|
| 初回開始 | mode=firstのrun_idの重複除去数 |
| 初回完了率 | 初回開始後24h以内の完了run / 24h観測期間を満たした初回開始run |
| 60秒達成割合 | ヒントなし/中断なし/continuous/60,000ms以内の初回完了run / 初回開始run |
| 完了時間中央値 | 初回完了runのelapsed_ms中央値。未完了が除かれることを併記 |
| 共有操作率 | share_intentを1回以上起こした初回完了run / 初回完了run |
| 共有流入開始 | source=shareで初めてプレイを開始した観測可能な匿名ID数 |
| 翌日継続 | 初回のUTC翌日に別のdailyを開始した匿名ID / 翌日観測可能な初回匿名ID |
| 7日後継続 | 初回のUTC7日後にdailyを開始した匿名ID / 7日観測可能な初回匿名ID |

割合は分母と期間を併記する。分母0や未取得はnull/未計測で、0%にしない。
チュートリアル、再挑戦、運営テスト、既知botは別扱い。bot排除で完全な実人数が得られるとは言わない。
共有APIの解決やコピー成功をSNS投稿完了と呼ばない。
初版は紹介者と被紹介者を確実に紐付けないため、正確なK-factorを出さない。

## 試遊1: 操作の検証
協力者20人程度、主にスマートフォン。ルール説明を読み上げずに開始してもらう。
最初の選択、回転、配置、戻し、無効配置からの回復を観察する。
16人以上が説明者の助けなしに最初の配置をできることを暫定目標とする。
困った操作を直してから、難しい問題を増やす。

## 試遊2: 難易度
複数問題を複数人へ割り当て、同じ人が同じ答えを知った状態で再計測した値を初回に混ぜない。
完了時間、ヒント、未完了、操作に迷った時間、自由な感想を確認する。
中央値45〜90秒は仮目標で、達成率とセットで調整する。
「1分」と宣伝して大半が数分かかるなら、問題を易しくするか訴求を修正する。

## 公開試験
日英で小さく公開し、まず人間と確認できる初回100件程度を集める。
サンプル数だけで成功扱いしない。共有リンクから新しい人が入り、本当に開始したかを確認する。
10〜14日以上の観測で、再訪する人がいるかを確かめる。
同じ日には全員同じ問題を維持する。実験するならCTA文・説明・導入だけにし、問題ルールは混ぜない。

## 改善ルール
開始前離脱が多い: 説明/読み込み/開始導線を確認。
始めるが配置できない: 操作を直す。
配置できるが完了しない: 難易度/ヒントを直す。
完了するが共有されない: カード文と共有する理由を直す。
共有操作はあるが流入がない: 固定URL、OG、コピー、SNS内ブラウザーの動作を確認。
初回は遊ぶが戻らない: 翌日問題の変化と再開の分かりやすさを確認。

## 収益化
初版の支払いは実装しない。継続する利用者が出てから追加問題パック・任意テーマの価値を小さく検証する。
価格をこの設計で確定しない。世界展開での税・表示・決済条件は、導入段階で別途調査する。
利用者に不利な時間延長課金、ヒント課金、順位購入はしない。
